# ADR-0001: Telegram bot as the only member-facing client in v1.0

- **Date:** 2026-05-16
- **Status:** Accepted
- **Deciders:** Lead Architect

## Context

The original manifesto specified a mobile app strategy in two phases: Phase 1 = responsive web, Phase 2 = React Native. The user clarified that for v1.0:

- Only the admin web is built.
- Member-facing experience is delivered through a Telegram bot.
- Mobile apps come later.

Members need to:
- see their plan, expiration date, visits remaining, tariff
- check in via QR code at the gym
- get notifications

## Decision

In v1.0, the Telegram bot is the **only** member-facing client. There is no member web portal, no mobile app. Bot capabilities:

- Account linking via one-time code generated by admin staff
- View plan, expiration, remaining visits
- Show **rotating QR code** for check-in
- Visit history
- Receive notifications

The bot is implemented as an aiogram module inside the FastAPI process, using webhook mode. Not a separate deployable.

## Consequences

**Positive:**
- Saves ~3 weeks of frontend work (no separate member app to design, auth, build).
- Telegram provides identity, push, and a polished UI for free.
- Single deployable means no IPC, no service coordination.

**Negative:**
- Excludes members who don't use Telegram.
- Bot UX has limits (no rich forms, limited UI elements).
- If we later add a member web app, the bot becomes a second client to maintain.

**Mitigations:**
- Track in pilot how many members refuse to install Telegram. If > 20%, accelerate member web portal.
- Bot UI stays minimal so it can be replicated as a thin client of the same API.

## Alternatives considered

- **Member web portal alongside admin web.** Rejected: 3+ weeks of additional work for v1.0.
- **PWA for members.** Rejected: still requires designing/building member-specific UI, plus push notification setup. Telegram solves push for free.
- **WhatsApp bot instead.** Rejected: WhatsApp Business API has cost + verification overhead; Telegram bot is free and instant.
