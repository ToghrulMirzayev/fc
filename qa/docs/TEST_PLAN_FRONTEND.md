# Тест-план — Frontend Admin Web Portal (FitnessCourt)

Этот документ описывает стратегии, сценарии и методы тестирования веб-приложения администратора **FitnessCourt** (Next.js 14 App Router, TailwindCSS, shadcn/ui).

---

## Легенда идентификаторов (Test ID Legend)
* **AUTH-F** (Authentication - Frontend) — формы логина, регистрации, выбор slug воркспейса, логаут, профиль сотрудника.
* **CRM-F** (Customer Relationship Management - Frontend) — список клиентов, фильтры, поиск, детали профиля, заморозка, защита от инъекций.
* **CHK-F** (Checkout & Payments - Frontend) — интерфейс приема платежей наличными, история оплат, табы способов оплаты, блокировка двойных кликов.
* **SCAN-F** (QR Scan & Check-in - Frontend) — интерфейс QR-сканера, доступ к камере, статус-баннеры и живая лента проходов.
* **BOT-F** (Telegram Bot Helper - Frontend) — отображение инструкций и генерация кодов связи с Telegram в интерфейсе.
* **OPS-F** (Operations & Catalog - Frontend) — отображение и создание тарифных планов (plans).
* **SYS-F** (System - Frontend) — дашборд KPI, адаптивность (мобильные шторки, Sidebar), темы (Dark / Light), обработка ошибок API (Error Boundary).

---

## 1. Область тестирования (Scope of Testing)

Объектом тестирования является веб-интерфейс администратора (Gym Owner / Staff):
1. **Авторизация и Signup**: Регистрация новой студии, двухэтапная форма входа (поиск slug организации -> ввод email/пароля).
2. **Дашборд аналитики**: Загрузка KPI виджетов, списки заканчивающихся абонементов, живой лог посещений.
3. **CRM: База клиентов**: Таблицы пользователей, поиск, фильтры по статусам, добавление клиентов.
4. **Профиль клиента**: Карточка пользователя, генерация кодов связи Telegram, заморозка/разморозка, назначение планов и история оплат.
5. **Создание тарифов (Plans)**: Каталог абонементов и форма создания нового тарифа.
6. **Сканер посещений**: Страница QR-сканера (доступ к камере) и лог проходов.
7. **Адаптивность и темы**: Корректность отображения на мобильных/планшетах, переключение Темной/Светлой тем.

## 2. Каталог тестовых сценариев (Test Scenarios)

### 2.1. Приоритет [P0] — Критические проверки (Critical)
- [ ] **AUTH-F01** — **`test_login_two_step_flow`**: Ввод валидного `slug` организации, подгрузка брендинга, ввод учетных данных, успешная авторизация и переход на дашборд.
- [ ] **CRM-F01** — **`test_assign_plan_flow`**: Выбор тарифа в профиле клиента, подтверждение операции и блокировка карты клиента до момента фиксации оплаты.
- [ ] **SCAN-F01** — **`test_scanner_feedback_success`**: Эмуляция успешного сканирования на `/checkins` -> отображение зеленого баннера прохода с именем клиента и проигрывание звука.
- [ ] **SCAN-F02** — **`test_scanner_feedback_error`**: Эмуляция невалидного QR -> отображение красного баннера ошибки с причиной (Expired, Frozen, No active plan).
- [ ] **CHK-F01** — **`test_record_cash_payment_flow`**: Поиск клиента на странице оплаты `/payments`, заполнение формы наличных (подгрузка суммы долга) и активация карты после отправки платежа.

### 2.2. Приоритет [P1] — Высокий приоритет (High)
- [ ] **AUTH-F02** — **`test_gym_owner_signup_validation`**: Проверка обязательных полей формы регистрации, маски телефона, валидации почты и сложности пароля.
- [ ] **AUTH-F03** — **`test_login_validation_errors`**: Проверка ошибок при несуществующем slug воркспейса или неверном пароле на форме входа.
- [ ] **AUTH-F04** — **`test_sign_out_confirmation`**: Клик по кнопке "Sign Out" на странице `/profile`, открытие подтверждающего модального окна, отмена или подтверждение логаута с редиректом.
- [ ] **SYS-F01** — **`test_dashboard_kpi_counters`**: Загрузка и отображение 4 основных карточек KPI (Active members, Revenue / Month, Check-ins today, Churn risk) с непустыми числовыми значениями.
- [ ] **SYS-F02** — **`test_responsive_sidebar_drawer`**: На мобильных разрешениях боковое меню скрывается в "гамбургер", открывается шторкой (drawer) и закрывается по клику вне меню.
- [ ] **SYS-F05** — **`test_api_error_boundary_graceful_handling`**: Имитация падения или недоступности API бэкенда (500 Internal Error) при загрузке страниц. Проверка работы глобального Error Boundary или Toast-уведомлений для предотвращения падения UI в белый экран.
- [ ] **CRM-F02** — **`test_members_table_rendering`**: Корректность колонок таблицы (Name, Status pill, Phone, Email, Plan, Expiry).
- [ ] **CRM-F03** — **`test_members_search_debounced`**: Поиск клиента по имени, телефону или email с проверкой debounce задержки при вводе.
- [ ] **CRM-F04** — **`test_members_status_filter_tabs`**: Фильтрация таблицы клиентов кликами по вкладкам (All, Active, Frozen, Expired, Inactive).
- [ ] **CRM-F05** — **`test_add_member_modal_validation`**: Открытие модального окна добавления, заполнение данных, валидация полей и появление нового клиента в списке.
- [ ] **CRM-F06** — **`test_member_info_edit`**: Изменение персональных данных клиента (телефон, email) в детальном профиле.
- [ ] **CRM-F07** — **`test_membership_control_actions`**: Заморозка абонемента по кнопке "Freeze 14d" (статус переходит в `frozen`), появление кнопки "Resume" и восстановление статуса `active` по клику.
- [ ] **CRM-F08** — **`test_xss_injection_safety_in_members`**: Ввод XSS-нагрузки (`<script>alert(1)</script>`) в поле имени/заметок при создании или редактировании карточки клиента. Проверка экранирования данных в таблице и профиле.
- [ ] **BOT-F01** — **`test_telegram_link_code_popup`**: Генерация и вывод 6-значного кода привязки Telegram-бота с инструкцией в карточке клиента.
- [ ] **OPS-F01** — **`test_plans_list_view`**: Отображение всех существующих тарифов спортзала в виде карточек.
- [ ] **OPS-F02** — **`test_create_plan_form`**: Заполнение полей тарифа (название, цена, длительность в днях, лимит посещений) и создание нового тарифа.
- [ ] **SCAN-F03** — **`test_live_visits_feed_rendering`**: Отображение лога последних визитов на дашборде с именами клиентов и временем прохода.
- [ ] **SCAN-F04** — **`test_camera_permission_handling`**: Запрос разрешений браузера на использование камеры при входе на `/checkins`.
- [ ] **SCAN-F05** — **`test_camera_permission_denied_fallback`**: Имитация отклонения пользователем прав на камеру. UI должен скрывать область сканирования и отображать разборчивую инструкцию по ручной активации разрешений в браузере.
- [ ] **CHK-F02** — **`test_member_lookup_in_payments`**: Поиск клиента по имени/телефону/email/ID на странице оплат и отображение списка кандидатов при множественном совпадении.
- [ ] **CHK-F05** — **`test_double_submit_prevention`**: Быстрый повторный клик по кнопкам отправки платежа ("Record cash payment") или назначения тарифа ("Assign plan") должен блокироваться переходом кнопки в состояние disabled, предотвращая создание дублирующих записей.

### 2.3. Приоритет [P2] — Средний/Низкий приоритет (Medium/Low)
- [ ] **SYS-F03** — **`test_expiring_memberships_alert_list`**: Проверка списка клиентов с истекающим сроком действия контрактов на дашборде.
- [ ] **SYS-F04** — **`test_dark_light_theme_toggle`**: Переключение тем через кнопку в шапке/сайдбаре и мгновенное применение CSS переменных темной/светлой темы.
- [ ] **CHK-F03** — **`test_payments_history_table`**: Таблица истории платежей за абонементы в детальном профиле клиента.
- [ ] **CHK-F04** — **`test_payment_methods_tabs`**: Отображение вкладок методов оплаты (Cash, Bank Transfer, Card, Online Checkout) на странице оплат с бейджами "soon" на неактивных методах.
- [ ] **AUTH-F05** — **`test_staff_profile_details`**: Отображение персональных данных сотрудника, названия зала и ссылки на персональный воркспейс на странице `/profile`.

## 3. Инструменты и автоматизация тестирования

Для автоматизации UI тестов используется:
* **Инструмент**: Python + Pytest + `pytest-playwright` (Sync API).
* **Паттерн**: Page Object Model (POM) + Scoped Components для переиспользуемых элементов (Sidebar, AppShell, Modals).
* **Среда запуска**: Локальный или CI запуск в headless режиме. Настройки в `conftest.py` задают ширину вьюпорта (1280x800 для десктопа, эмуляция мобильных устройств для адаптивности).
