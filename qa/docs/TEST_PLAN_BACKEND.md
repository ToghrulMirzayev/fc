# Тест-план — Backend API & Telegram Bot (FitnessCourt)

Этот документ описывает стратегии, сценарии и методы тестирования бэкенд-сервиса платформы **FitnessCourt** (FastAPI, PostgreSQL, Redis, Celery, aiogram).

---

## Легенда идентификаторов (Test ID Legend)
* **AUTH-B** (Authentication - Backend) — авторизация сотрудников, сессии, JWT-токены, публичная регистрация.
* **CRM-B** (Customer Relationship Management - Backend) — карточки клиентов, управление абонементами, статусы.
* **CHK-B** (Checkout & Payments - Backend) — проведение транзакций, платежи, проверка доступных методов.
* **SCAN-B** (QR Scan & Check-in - Backend) — обработка проходов по QR-кодам, валидация signatures HMAC, анти-флуд.
* **BOT-B** (Telegram Bot - Backend) — линковка Telegram аккаунтов, клавиатуры, генерация QR и команды бота.
* **OPS-B** (Operations & Catalog - Backend) — справочники тарифов, операционная деятельность.
* **SYS-B** (System - Backend) — общесистемные требования, изоляция баз данных (Multi-tenancy).

---

## 1. Область тестирования (Scope of Testing)

Объектом тестирования является бэкенд-сервер, предоставляющий REST API для веб-админки и вебхук-эндпоинт для Telegram-бота:
1. **Tenant Isolation (Изоляция данных)**: Проверка корректности фильтрации запросов по `tenant_id` на уровне БД.
2. **REST API Endpoints**: Тестирование всех групп эндпоинтов (Public, Auth, Dashboard, CRM, Operations).
3. **Telegram Bot (aiogram webhook)**: Проверка линковки аккаунтов, генерации временных QR-кодов и ответов бота.
4. **Безопасность и лимиты**: Валидация подписей QR-кодов (HMAC), одноразовости токенов в Redis, лимитов брутфорса (Rate Limits).

## 2. Каталог тестовых сценариев (Test Scenarios)

### 2.1. Приоритет [P0] — Критические проверки (Critical)
- [ ] **SYS-B01** — **`test_db_isolation_enforced`**: Проверка, что при обращении к API с сессией Tenant A невозможно получить или изменить данные (клиентов, оплат, визитов) Tenant B.
- [ ] **AUTH-B01** — **`test_jwt_token_lifecycle`**: Успешное получение JWT пары (Access + Refresh), валидация времени жизни токенов, ротация Refresh-токенов.
- [ ] **AUTH-B02** — **`test_jwt_signature_tampered`**: Попытка выполнить запрос к защищенным эндпоинтам с JWT-токеном, у которого подделана подпись (signature). Сервер должен возвращать 401 Unauthorized.
- [ ] **CRM-B01** — **`test_assign_membership_plan`**: Назначение клиенту абонемента, расчет даты окончания и проверка статуса.
- [ ] **CHK-B01** — **`test_payments_cash_recording`**: Регистрация оплаты абонемента наличными, запись в историю оплат члена клуба, автоматическая разблокировка абонемента.
- [ ] **SCAN-B01** — **`test_qr_code_verification_success`**: Проверка валидности HMAC-подписи QR-кода при запросе от сканера на `/checkins/scan`.
- [ ] **SCAN-B02** — **`test_qr_code_expiration`**: Попытка сканирования просроченного QR-кода (> 30 сек) должна возвращать ошибку.
- [ ] **SCAN-B03** — **`test_qr_code_replay_protection`**: Проверка, что после первого успешного сканирования токен QR-кода заносится в Redis и повторный запрос с тем же токеном отклоняется.
- [ ] **SCAN-B04** — **`test_qr_code_signature_invalid`**: Попытка сканирования QR-кода с неверной или подделанной HMAC-подписью должна возвращать ошибку валидации подписи (400 Bad Request).
- [ ] **SCAN-B05** — **`test_qr_scan_unpaid_or_frozen`**: Попытка прохода по QR-коду клиента с неоплаченным или замороженным абонементом должна отклоняться с кодом ошибки `unpaid` или `frozen`.
- [ ] **BOT-B01** — **`test_bot_account_linking`**: Генерация 6-значного кода привязки в админке, связывание `telegram_user_id` с карточкой клиента в боте, валидация просрочки (> 10 мин) и повторного использования.
- [ ] **BOT-B02** — **`test_bot_qr_unlocked_check`**: Проверка, что QR-код генерируется и отправляется пользователю только при наличии активного и оплаченного абонемента. В случае неоплаченного абонемента бот должен выводить сообщение о блокировке карты.

### 2.2. Приоритет [P1] — Высокий приоритет (High)
- [ ] **SYS-B02** — **`test_subdomain_tenant_resolving`**: Проверка middleware определения `tenant_id` на основе поддомена (`iron.fitnesscourt.com`) или HTTP-заголовка `X-Tenant-Slug`.
- [ ] **SYS-B03** — **`test_cors_policy_protection`**: Проверка, что запросы к API с неодобренных в CORS источников (доменов, отличных от разрешенного списка) отклоняются сервером.
- [ ] **AUTH-B03** — **`test_signup_gym_owner`**: Регистрация новой студии (создание tenant, owner, базовых настроек) с валидацией обязательных полей.
- [ ] **AUTH-B04** — **`test_lookup_workspace_by_slug`**: Получение публичных брендинговых настроек спортзала (логотип, цвета, название) по slug.
- [ ] **AUTH-B05** — **`test_login_rate_limiting`**: Проверка блокировки IP/аккаунта при превышении лимита неудачных попыток входа на `/auth/login`.
- [ ] **AUTH-B06** — **`test_refresh_token_endpoint`**: Обновление пары JWT-токенов через POST `/auth/refresh` с использованием валидного Refresh-токена.
- [ ] **AUTH-B07** — **`test_current_user_profile`**: Эндпоинт `/auth/me` возвращает корректную модель сотрудника и права роли (Owner/Manager/Receptionist).
- [ ] **CRM-B02** — **`test_members_crud`**: Создание, чтение, обновление и удаление карточки клиента.
- [ ] **CRM-B03** — **`test_membership_freeze_and_resume`**: Заморозка абонемента (клиент переходит в статус `frozen`, дата окончания абонемента сдвигается), разморозка (переход в `active`), проверка автоматического снятия заморозки Celery-задачей.
- [ ] **CRM-B04** — **`test_members_lookup_detailed`**: Проверка поиска клиента по UUID, префиксу `MBR_`, номеру телефона, email или имени через `/members/lookup`. Проверка возврата единичного совпадения или списка кандидатов.
- [ ] **OPS-B01** — **`test_plans_crud`**: Добавление новых тарифов для спортзала, редактирование цены и лимитов посещений.
- [ ] **SCAN-B06** — **`test_manual_checkin`**: Ручная отметка прохода администратором через админку для клиента без Telegram-кода.
- [ ] **SCAN-B07** — **`test_checkins_feed_retrieval`**: Получение ленты последних посещений `/checkins/feed` и общего числа визитов за сегодня (`today_count`).
- [ ] **BOT-B03** — **`test_bot_linking_rate_limits`**: Ограничение попыток линковки (не более 5 попыток в час с одного Telegram ID).
- [ ] **BOT-B04** — **`test_bot_start_menu`**: Проверка ответов команды `/start` для нелинкованного и линкованного пользователей, отображение клавиатуры меню.
- [ ] **BOT-B05** — **`test_bot_menu_navigation`**: Проверка ответов бота при кликах на кнопки: "Мой план" (My plan), "Показать QR" (Show QR), "История" (History) и "Помощь" (Help) в зависимости от локали.

### 2.3. Приоритет [P2] — Средний/Низкий приоритет (Medium/Low)
- [ ] **AUTH-B08** — **`test_billing_plans_retrieval`**: Список доступных тарифов для владельцев спортзалов на использование платформы FitnessCourt.
- [ ] **AUTH-B09** — **`test_get_discount_flag`**: Проверка возврата состояния фича-флага `signup_discount` (активен/неактивен, процент скидки и промо-сообщение).
- [ ] **CRM-B05** — **`test_member_visits_history`**: Получение истории посещений конкретного члена клуба через эндпоинт `/members/{member_id}/visits`.
- [ ] **CHK-B02** — **`test_list_payment_methods`**: Получение списка доступных методов оплаты через `/payments/methods` и статуса их доступности (`cash` — активен, остальные — `soon`).
- [ ] **CHK-B03** — **`test_list_member_payments`**: Проверка получения истории всех платежей члена клуба через `/payments/members/{member_id}`.
- [ ] **BOT-B06** — **`test_bot_history_limit`**: Кнопка "История" должна возвращать не более 5 последних посещений пользователя.
- [ ] **BOT-B07** — **`test_bot_localization`**: Ответы бота на языке, соответствующем `locale` пользователя (русский/английский).

## 3. Инструменты и автоматизация тестирования

Для автоматизации тестов бэкенда используется:
* **Инструмент**: Python + Pytest (синхронный/асинхронный запуск).
* **Клиент**: `httpx` (асинхронные HTTP-запросы) или стандартная библиотека `requests`.
* **Тестовая база данных**: Подъём тестовой PostgreSQL в Docker-контейнере, накат миграций Alembic перед запуском тестов и очистка таблиц (DB clean) после каждого теста.
